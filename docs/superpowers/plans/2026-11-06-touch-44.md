# Touch targets of 44 px Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Everything a finger taps in the Qt window is at least 44 x 44 px, proved by tests that read the real sizes of the built window.

**Architecture:** The sizes were already changed in `qtui/qml` (commit `2882cc8`, built before the spec). This plan adds the tests that were missing, makes each one fail against the old sizes first, then checks the docs and the window. Code changes come only if a test finds a real problem.

**Tech Stack:** QML (Qt Quick), PySide6, `unittest` (`tests/test_qtui.py`).

**Spec:** `docs/superpowers/specs/2026-11-06-touch-44-design.md`

## Global Constraints
- Tap area of everything tapped: at least 44 x 44 px (`Theme.touchMin` = 44; `Theme.touchSize` no longer exists).
- Shortest window 596 px (`Theme.windowMinHeight`), narrowest 640 px (`Theme.windowMinWidth`), Deck 800 px tall.
- Every size comes from `qtui/qml/Theme.qml`; no new colour, font or loose number in a QML file.
- Drawn shapes keep their size: "i" circle 24 px (`Theme.infoDot`), flag 32 x 24, switch 38 x 22.
- Commits: Conventional Commits, no Claude co-author line, never push.

## Review Focus
- Portuguese text is longer than English: a menu row or a choice button must still be 44 px and not clip (checked with the language set to `pt-BR` in Task 2).
- The keyboard focus ring of a flag and of the "i" circle stays around the drawn shape, not around the whole 44 px box (checked in Task 1).
- A window made exactly 640 x 596 shows the footer links fully inside the window (Task 3).
- Two Steam accounts show the account choice buttons on Home; they must also be 44 px (Task 1).
- A tap on the transparent part of a flag box still picks the language (Task 1).
