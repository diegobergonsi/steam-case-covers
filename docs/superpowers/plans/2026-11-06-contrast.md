# Contrast to the recommended rule Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every colour in `qtui/qml/Theme.qml` meets WCAG AA (text 4.5 to 1, outlines 3 to 1) on every fill it is drawn on, proved by a test for each pair.

**Architecture:** Only three colour values change (`faint`, `done`, `edge`). A new test computes contrast for a table of (colour, fill) pairs from `Theme.qml` itself, including the menu fill and the hovered raised fill worked out the way Qt does. The docs follow the values and a test keeps docs and `Theme.qml` equal.

**Tech Stack:** QML (`Theme.qml`), `unittest` (`tests/test_qtui.py`, class `Tokens`).

**Spec:** `docs/superpowers/specs/2026-11-06-contrast-design.md`

## Global Constraints
- AA: text colours 4.5 to 1, outlines and control shapes 3 to 1, measured on every fill listed in the spec.
- New values: faint `#8a9db1`, done `#6aab3e`, edge `#637f9a`. Nothing else changes colour: muted `#93a7bb` stays (the owner chose option A).
- Switched-off controls (60% opacity) are not measured.
- Colours live only in `qtui/qml/Theme.qml`; `docs/ui-guide.md`, `docs/DESIGN.md` and `Theme.qml` hold the same hex values.
- Commits: Conventional Commits, no Claude co-author line, never push.

## Review Focus
- The locked-step text and the disabled main button are faint on the raised fill: pinned by the pair `faint` on `raised` (a text field is the window colour, so its placeholder is `faint` on `bg`).
- The off switch and the outline of a field are `edge` on the card and on the raised fill: pinned by `edge` on `card` and `raised`.
- A locked step in the menu is faint on the menu panel, which is the window colour made darker by 1.3 (`navBg`): pinned by `faint` on `navBg`.
- A choice button under the mouse is the raised fill made lighter by 1.15: pinned by `text` and `muted` on that fill.
- The scroll bar is `edge` on the card colour: pinned by `edge` on `card`.

### Task 1: The pairs, the three colours and the docs' values

**Files:**
- Modify: `qtui/qml/Theme.qml` (the three colour values), `docs/ui-guide.md` (colour table), `docs/DESIGN.md` (frontmatter and the contrast sentence)
- Test: `tests/test_qtui.py` (class `Tokens`)

**Interfaces:**
- Consumes: `Tokens.theme()` (dict of colour name to hex from `Theme.qml`), module function `contrast(a, b)` (WCAG ratio of two `#rrggbb`).
- Produces: `Tokens.fills()` returning `{"bg", "navBg", "card", "raised", "raisedHover"}` as hex, where `navBg` is `bg` with its HSV value divided by 1.3 and `raisedHover` is `raised` with its HSV value multiplied by 1.15 (capped at 1), both as Qt's `darker` and `lighter` do.
