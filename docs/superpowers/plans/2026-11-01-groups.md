# Groups of covers made by hand: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans (inline, one task at a time, test first, commit per task). Steps use `- [ ]`.

**Goal:** named, saved groups of hand-made covers, with Steam-case colours, protected from the usual flow and repainted or reset only when ticked.

**Architecture:** a small `groups.py` store (JSON in the covers folder); a PNG note `steamcase-group` on hand-made covers makes the engine's folder checks skip them; `make_covers` gets per-game colours, group ids and a repaint set; the window gets group lists in the Case, Make and Reset steps.

**Tech stack:** Python 3, Pillow, PySide6/QML, unittest.

**Spec:** `docs/superpowers/specs/2026-11-01-groups-design.md`

## Global constraints
- Conventional Commits; no attribution lines; never push without asking; PR text simple.
- Test first for everything; the suite stays green with and without Qt (`scratchpad/t.sh`).
- Console and group covers have no theme and no gold treatment; marks only on completed games.
- Never mention Flatpak, Flathub or AUR in public files.

## Review focus
1. A damaged `groups.json` (not JSON, wrong shape, duplicate or empty or very long names, appids that are text) loads as "no groups", never raises, never deletes covers.
2. A hand-made cover whose group is missing from the file is still left alone by the usual flow.
3. A group member whose cover or game is gone is dropped without an error.
4. Gold group: the case is gold, and a non-100% game gets no marks.
5. Repaint then delete: a ticked group's covers take the usual look and the group is gone; an unticked one is untouched, including after a failed Make (nothing is deleted before the covers exist).

### Task 1: the groups store
**Files:** create `groups.py`, `tests/test_groups.py`.
**Interfaces (produces):**
- `groups.load(covers_dir) -> list[dict]`: each `{"id": str, "name": str, "case": {"platform": str} | {"tone": [hue, sat, val]}, "games": [int]}`; a missing or damaged file gives `[]`, a damaged entry is dropped.
- `groups.save(covers_dir, groups)`: atomic write (temp file then rename) of `covers_dir/groups.json`.
- `groups.assign(groups, name, case, appids) -> (groups, group_id)`: finds the group by name or makes one (new id), moves the games into it (taking them out of other groups), deletes empty groups, validates (name 1 to 40 characters, no control characters, trimmed; case valid: a platform of `sc.PLATFORMS` or a tone with hue 0 to 359, sat and val 0 to 100): `ValueError` with a plain sentence.
- `groups.delete(groups, group_id) -> groups`; `groups.members(groups, ids) -> set[int]` appids of those groups; `groups.drop_games(groups, appids)`.

### Task 3: making covers in groups
**Files:** modify `steamcase.py`; tests in `tests/test_steamcase.py` (class `GroupMake`).
**Interfaces:** `make_covers(..., tones=None, groups=None, repaint=None)`.
- `tones`: `{appid: (hue, sat, val)}` colour of a Steam-case game in the manual dict; ignored for console games and the usual flow; invalid tone: `ValueError` before any lookup.
- `groups`: `{appid: group_id}` written as the note; in the manual flow a cover is kept only if its group note equals the wanted one.
- `repaint`: set of appids whose protection is lifted in the usual flow: a console or group cover is rebuilt as a normal cover.
- The usual flow (`platforms is None`) leaves any `cover_by_hand` cover alone unless its appid is in `repaint`, counted in `res["platforms"]` as today (rename the counter's docstring to "covers by hand").
- `covers_in_other_case(covers_dir, platforms, tone, treatment, completed, tones=None, groups=None)` counts a Steam-case game whose cover has another colour or group, as it counts another console.
- `reasons.platform_replace_reason(..., tones, groups)` passes them on; new `reasons.group_repaint_reason(covers_dir, repaint_groups)`: `(title, text)` listing each ticked group by name and count, or `None`.
- [ ] Failing tests: Steam-case game in red gets the red case and the note; two groups with two colours in one run; gold tone makes a gold-hue case; a completed game gets the marks and a non-completed one does not, in a gold group too; a kept cover is not rebuilt, a changed colour or group rebuilds; the usual flow leaves group and console covers alone, and rebuilds those in `repaint` (note gone, normal look); recognition of every case with `is_steamcase_cover`; bad tones refused before any lookup; the reason texts.
- [ ] Run: FAIL. Implement. Run the whole suite: PASS. Commit `feat: games in a group get their own colour, and the usual flow leaves them alone`.

### Task 5: Make saves groups and the usual Make repaints them on request
